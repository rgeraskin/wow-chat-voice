# WoW Chat Voice — заметки для разработки

Описание для игроков — в [README.md](README.md). Здесь — как всё устроено, почему так, и как проверять.

## Почему полоска пикселей

- WoW с 11.2 загружает только подписанные DLL голосов SAPI: сторонние голоса видны в списке озвучки игры, но молчат. Подписывать DLL и подкладывать их игре — не вариант (риск бана).
- Лог чата (`/chatlog`) игра пишет на диск только при выходе из мира.
- Аддоны не могут писать файлы во время игры. Остаётся экран: аддон рисует строку ячейками, программа снимает окно игры. Ничего не внедряется в процесс игры.

## Устройство

- `addon/WowChatVoice/` — аддон (WoW Forever, интерфейс 16001). Порядок загрузки — в `WowChatVoice.toc`.
  - `Protocol.lua` — кодирование строки в ячейки (чистые функции; тот же файл грузит тест через LuaJIT).
  - `Strip.lua` — полоска у верхнего края: очередь строк, удержание, пустой кадр.
  - `Dictionary.lua` — стандартный словарь (`D.DEFAULT`), слои (правки игрока поверх стандарта), применение слов/фраз/основ, сортировка; регулярки только хранит и передаёт.
  - `Core.lua` — события чата, проверка «видно в окнах чата», сбор строки (`ns.Send`), управляющие кадры, передача регулярок, `/wcv`.
  - `UI.lua`, `Options.lua`, `DictionaryWindow.lua`, `VoicesWindow.lua`, `Minimap.lua` — окна и значок.
  - `VoiceList.lua` — список голосов Windows; пишет программа (в репозитории — пустая заготовка).
  - `Icon.tga` — рисует `tools/make_icon.py` (`uv run --with pillow tools/make_icon.py`).
- `companion/` — программа для Windows (Python), пакет `wcv`, запуск `WowChatVoice.cmd` (создаёт `.venv`, ставит `requirements.txt` и `requirements-f5.txt`).
  - `__main__.py` — настройки по умолчанию (`DEFAULT_CONFIG`, дописываются в `config.json`), журнал, главный цикл: снимок → декодирование → разбор → текст → движок.
  - `window.py`, `capture.py` — окно WoW и его снимок; `protocol.py` — декодер полоски и разбор строки.
  - `dictionary.py` — регулярки (приём частями по полоске, чтение из SavedVariables), формы по числу, порядковые; `morph.py` — склонение замен после предлогов; `text.py` — ударения (RUAccent), числа словами с согласованием.
  - `engines.py` — какой движок читает строку, ленивая загрузка и выгрузка F5; `speech.py` — голоса Windows (SAPI); `f5engine.py` — F5-TTS; `intonation.py` — вопросительная интонация; `audio.py` — проигрыватель.
  - `catquest.py` — банк образцов из CatQuest_Voices; `refcheck.py` — проверка образцов Whisper; `assign.py` — распределение голосов; `voicelist.py` — `VoiceList.lua` для аддона; `launch.py` — запуск игры через Battle.net.
- `companion/tests/` — тесты (см. ниже).

## Конвейер текста

1. Аддон: разметка чата убирается (цвета, ссылки, иконки), «+» из чата становится словом «плюс» (дальше «+» — только ударение), скобки-смайлики — точкой. Затем слова, фразы и основы словаря; замены помечаются `\x02…\x03`.
2. Программа: замены аддона склоняются после предлогов (`morph.py`, если включено), затем регулярки словаря (их замены тоже помечаются и склоняются), формы по числу `N [a|b|c]` и порядковые `<N>`.
3. Ударения: словарные «+» главнее, остальное — RUAccent с учётом контекста.
4. Числа словами (`num2words`), согласованные со словом после числа через pymorphy3 (`text.agree`): для 1 — род и падеж слова, для 2 — род, в косвенных падежах множественного — падеж всего числительного. Слова, которых нет в словаре pymorphy3 (сленг), не трогаются: его догадка по окончанию часто неверна («2 дамагера» он считает женским родом).
5. F5: строка делится на части — подряд идущие утверждения вместе, каждый вопрос отдельно; каждая часть синтезируется и получает свою интонацию, части склеиваются с паузой 0,15 с.

Порядок важен для правил с контекстом: регулярки видят текст уже после замен аддона. Например, «кд» к этому моменту уже «кулд+аун», поэтому правила секунд и серебра ждут оба варианта.

## Протокол полоски (версия 1)

- Ячейка — квадрат `cell` × `cell` физических пикселей (по умолчанию 2), ряд ячеек от левого верхнего угла клиентской области (`stripFrom = "left"`) или от правого (`"right"`); программа читает оба направления. Справа ячейки закрывает миникарта у верхнего края: она рисуется поверх любых фреймов, и длинные кадры обрезаются (пустой кадр помещается, поэтому «связь есть», а строки не читаются). `rows` рядов (по умолчанию 1).
- Под ячейками — чёрная полоса на всю ширину; ячейки почти чёрные, всё сливается в одну тёмную линию.
- Цвет ячейки — три канала по 4 уровня: 0, 12, 24, 36 (из 255), то есть 6 бит на ячейку. Ярче — заметнее в игре (цветные ячейки на 0–72 бросались в глаза); темнее — меньше запас по гамме: при гамме g уровень L становится 255·(L/255)^g, и при шаге 12 уровни различаются примерно до g = 1,2 (тест держит 1,1 и 1,2 с шумом).
- Ячейки 0–1: синхронизация (3,0,3) и (0,3,0). Ячейки 2–5: калибровка, все каналы на уровнях 0, 1, 2, 3 — программа берёт пороги посередине между ними, поэтому уровни можно менять только в аддоне.
- Дальше поток битов, старший первым: версия (4), номер строки (16), длина в байтах (12), CRC-16/CCITT-FALSE (16) по двум байтам номера и байтам строки, затем байты строки (UTF-8).
- Строка: `тип␟отправитель␟раса␟пол␟класс␟канал␟параметры␟текст[␟исходный текст]`, разделитель `\x1f`. Параметры — `rate=100;vol=100;voice=f5;decl=1;raw=1`: скорость и громкость в процентах, движок `f5`/`sapi`, склонение, есть исходный текст (он последним: при нехватке места обрезается он). Пол 2 — мужской, 3 — женский. Служебные типы: `control` (настройки: движок, выключенные голоса Windows `off=`), `regex` (часть набора регулярок: `id=;part=;of=`), `stop`, `reset`; неизвестные типы программа не читает вслух.
- Строка держится не меньше 0,25 с (программа снимает окно 20 раз в секунду), через 0,5 с без новых строк полоса возвращается к пустому кадру (14 ячеек). Номер строки при загрузке аддона случайный: программа пропускает то, что было на полоске до её запуска.
- Регулярки идут кадрами до 480 байт с контрольной суммой набора: при входе в игру и через 2 с после правки. Раз в 2 минуты аддон шлёт короткий кадр настроек, а полный набор — только если он менялся в этой сессии: иначе программа, запущенная позже игры, прочтёт тот же набор из SavedVariables (`regexes`), а каждый такой кадр — черта на полэкрана.
- Диагностика: декодер различает «полоски нет» и «полоска есть (синхронизация и калибровка на месте), но кадр не сходится» (`protocol.last_failure`); второе дольше секунды — запись в журнал.

## Словарь на слоях

- Стандарт (`D.DEFAULT`) живёт в аддоне; в SavedVariables — только правки игрока, `dictionaryEdits = { lines = { [ключ] = "блок" }, removed = { [ключ] = true }, header = "…" }`: изменённые и свои записи с комментариями над ними, пометки «удалено», шапка, если менялась. Итог (`D.Text()`) — стандарт с правками, отсортированный; окно словаря показывает итог, а при правке `D.SetText` считает разницу со стандартом.
- Ключ записи (`D.KeyOf`): у слов — нормализованные слова (`*` для основы), у регулярки — шаблон (всё до последнего `=`), так что правка замены — та же запись.
- Обновление аддона ничего не мигрирует: нетронутые записи получают новый стандарт, правленые остаются, удалённые не возвращаются, новые появляются. Если меняется шаблон стандартной регулярки (ключ), старый → новый ключ записывается в `D.RENAMED`: у правившего или удалившего старую новая рядом не появится.
- Итоговые регулярки аддон кладёт в SavedVariables отдельно (`regexes`): их читает программа, пока игра не передала набор по полоске.
- Сортировка: русские записи по алфавиту, латиница, цифры и символы, регулярки в конце; комментарии переезжают с записью под ними, верхний блок — шапка. `D.Text()` собирает блоки сам: `D.Sort` считает шапкой все комментарии до первой записи и прихватил бы комментарий случайного первого блока.
- Задел: стандарт с GitHub как слой между встроенным и правками (программа скачивает и кладёт `RemoteDictionary.lua` в папку аддона, как `VoiceList.lua`; аддон берёт его при `/reload`, если версия новее). Нужны `D.RENAMED` вместе со словарём и проверка регулярок при загрузке (компиляция, длина, прогон с таймаутом — от катастрофического перебора).

## F5-TTS и банк голосов

- Модель `Misha24-10/F5-TTS_RUSSIAN` (`F5TTS_v1_Base_v2`, CC BY-NC), `nfe_step` 16: около 0,8 с на строку на RTX 5070 Ti, около 2 ГБ видеопамяти. Синтез и воспроизведение в разных потоках. F5 загружается, только пока в аддоне выбраны голоса рас, и выгружается при выборе голосов Windows.
- F5 клонирует голос по образцу (5–12 с записи и её точный текст) при каждом вызове. Образцы вырезаются при первом запуске из установленного у пользователя CatQuest_Voices (`catquest.py`: разбор `Index.lua` через `lupa`, отрезок из целых предложений по субтитрам пака) и хранятся в `voices/`.
- Проверка образцов (`check_refs`): каждый отрезок слушает Whisper large-v3-turbo; если слова расходятся с субтитрами (сходство < 0,85 — в отрезок попал кусок соседней фразы, и F5 повторял его перед каждой репликой), берётся следующий отрезок.
- Длина фразы: `fix_duration` = образец + строка × `f5_margin` (1,25) + `f5_tail` (0,5 с) — без запаса F5 обрезал последние слоги (на 40 фразах 10 голосов: 14 обрезанных без запаса, 0 с ним).
- Разнообразие: голоса пака по расе и полу плюс копии каждого со сдвигом тембра (`voice_shifts`, ±1,5 полутона, передискретизацией образца). Распределение с памятью (`assignments.json`, `assign.py`): новому персонажу — наименее занятый голос среди слышанных за 30 минут, сначала голоса пака, потом копии. Расы без голосов в CatQuest — по родственным (`RACES` в `assign.py`).
- После синтеза (и для голосов Windows): тишина перед речью обрезается (остаётся 50 мс), громкость выравнивается одним множителем на фразу (~−22 дБ, пик не выше 0,95 — интонация не меняется), крик +3 дБ, шёпот −4 дБ (`kind_gain_db`), громкость аддона (до 200 %) с мягким ограничением пиков выше 0,8 (`f5engine.limit`).
- Обходы: `torchaudio.load` через `soundfile` (torchaudio 2.11 декодирует через `torchcodec`, которому нужны DLL FFmpeg); нулевые `token_type_ids` для ONNX-моделей RUAccent. torch закреплён `==2.11.0+cu128` (иначе pip ставит CPU-сборку). Модели после первой загрузки берутся из кэша без сети (`.models_ready` → `HF_HUB_OFFLINE`).

## Интонация вопросов

- F5 сам вопросительной интонации почти не делает. Прогон 20 вопросов × 4 голоса: подъём ≥ 2 полутонов в конце да/нет-вопроса — в 5 % случаев, и с «?», и с точкой (знак вопроса модель не учитывает); `??`, `?..`, `cfg_strength` 3–4 не помогают; лучший из трёх seed находит подъём в 22 % случаев. Вопросы с вопросительным словом F5 в основном и так роняет к концу (68–85 %) — для них это правильно.
- Образцы с вопросом в конце (`f5_question_refs`, выключено) не помогли: голоса CatQuest сами синтезированы, и их «вопросы» такие же плоские.
- Поэтому `intonation.py` (Praat PSOLA через `praat-parselmouth`: меняется тон, тембр и темп нет), `question_intonation` в `config.json`:
  - да/нет-вопрос («Идёшь с нами?»): последние 0,45 с голоса поднимаются до +7 полутонов над медианой реплики (`yes_no_rise_st`); последний слог, если F5 его погасил («гру-ппу»: «-пу» после смычки на 15–20 дБ тише), поднимается до уровня на `yes_no_end_db` (8) дБ ниже громких мест (90-й перцентиль громкости по 10-мс кадрам);
  - вопрос с вопросительным словом («Кто идёт?», «Ну а где танк?», частицы в начале пропускаются, «кто-нибудь» — не вопросительное слово): пик +6 полутонов на вопросительном слове (`wh_peak_st`), конец не трогается. Место слова — по номеру его ударного гласного среди гласных реплики в отрезке звучания; против Whisper ошибка около 0,12 с, поэтому пик широкий (0,16 с) и поднимает всё слово.
  - Пробовали и отказались: занижение начала да/нет-вопроса (на слух не отличается), растяжка конца (не слышна — дело было в громкости), подъём на первом слове вместо конца.
- Только для F5; без parselmouth звук не меняется.

## Голоса Windows (SAPI)

- pywin32, синтез в память (`SpMemoryStream`, 22 кГц 16 бит моно), проверка на обрезанный звук по длине текста.
- Голос игрока — рандеву-хешированием по имени и полу (у кого больше хеш пары «имя + голос»): выключение голоса меняет голос только у его игроков.
- Ударения — как принимает каждый движок (`stress`): RHVoice — U+0301, Silero — «+», Edge — без ударений (читает «+» вслух и не понимает U+0301).
- Строки латиницей без кириллицы — английскими голосами Windows.

## Захват

- Windows Graphics Capture (`windows-capture`) по окну игры: работает, когда окно закрыто другими; смещение клиентской области — через `DwmGetWindowAttribute`. Без него — снимок экрана `mss` (игра должна быть сверху). Свёрнутую игру не видит ни один способ.
- Проверять захват можно только в сессии пользователя: из SSH снимок экрана запрещён и окон нет.

## Тесты

```
python3 -m unittest discover -s companion/tests
cd addon/WowChatVoice && luajit ../../companion/tests/ui_mock.lua && luajit ../../companion/tests/dictionary_layers.lua
```

- `test_protocol.py` — кодировщик аддона (через LuaJIT) → отрисованная полоса (гамма, шум, ячейки 1–4 px, два ряда, полоса справа, перекрытая полоса) → декодер программы.
- `test_logic.py` — ударения, распределение голосов, разбор строки, регулярки, громкость, ограничитель, вопросы, согласование чисел; `test_morph.py` — склонение; `test_engines.py` — выбор движка. Тесты с numpy, pymorphy3 и num2words пропускаются без них: `uv run --with numpy --with pymorphy3 --with pymorphy3-dicts-ru --with num2words python -m unittest discover -s companion/tests`.
- `ui_mock.lua` — все окна аддона на заглушках WoW API, строки полоски, чтение только видимого в окнах чата, настройки переживают открытие окна.
- `dictionary_layers.lua` — слои словаря: ключи, правки, удаления, новый стандарт, переименование шаблона.

## Проверка на Windows

Разработка шла на Mac, проверка — на Windows-машине с игрой по SSH. Раскладка: файлы `addon/WowChatVoice/` (кроме `VoiceList.lua`, его пишет программа) — в `Interface\AddOns\WowChatVoice\` клиента, `companion/wcv/*.py` — в папку программы. Аддон подхватывает изменения после `/reload`, программа — после перезапуска. PowerShell-команды — файлом через `-File` (Defender блокирует `-EncodedCommand`).

## Исследования

- **XTTS v2** (кандидат для других языков): одна модель на 17 языков, клонирует без текста образца, потоковый синтез (первый звук ~0,47 с против ~1,1 с у F5). Минусы: нет управления ударением (частично спасает дефис: «Ко-пи деньги»), бормотание после конца фразы, лицензия CPML. Для русского F5 лучше: ударения через `+`. Fish Speech и Vosk TTS не подошли.
- **Образцы из клиента игры**: в клиенте с русской локализацией лежат записи живых актёров — голосовые эмоции персонажей по расе и полу, приветствия NPC, в ритейле — озвученные диалоги с точным текстом в `BroadcastText`. Это источник образцов для ритейловых рас и, возможно, лучше CatQuest (живая просодия). Достаются из хранилища CASC только чтением, у пользователя на компьютере, не распространяются.
- **Пунктуация перед синтезом**: в чате вопрос часто без «?», и тогда ни разбиение, ни интонация вопроса не срабатывают. Правило — только добавлять знаки, не исправлять. Варианты от дешёвых к дорогим: правила (вопросительное слово в начале, частица «ли»), RUPunct_small (BERT, MIT, есть INT8 ONNX), RUPunct_medium/big, Silero TE, `sbert_punc_case_ru`, маленькая языковая модель. Сравнить на базе строк `исходно:` из журналов с ручной разметкой: доля верно поставленных «?», ложные «?» на утверждениях, запятые отдельно, время и память.
- **ElevenLabs** как необязательный облачный движок: хороший русский и мгновенное клонирование по тем же образцам; минусы — платно (живой чат — десятки тысяч символов за вечер), чат уходит на сервер, нужна сеть.
